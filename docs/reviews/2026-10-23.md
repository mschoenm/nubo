`main` didn't move during the review. It looked for bugs, breaks of the rules in `AGENTS.md`,
idiomatic Rust, the code style, doc comments and the docs. The maintainer asked for larger fixes

### The bugs fixed

The most important first:

1. **A battery save that couldn't be read was treated as missing.** A `.sav` or `.rtc` that is
   there but unreadable (permission denied, an I/O error, a broken localStorage entry) made the game
   start on blank RAM, and its first save then replaced the player's file. Now the player is told,
   and nothing is written to that save for the rest of the session.
2. **A new MBC3 clock counted from 1970.** Without a saved `.rtc`, the cartridge clock started at
   time 0 on the wall clock. So a new Pokémon Gold, Silver or Crystal read day 269 with the day
   carry set at its first latch. It now starts at the time the cartridge goes in. On emulated time,
   which the tests and benchmarks use, it still starts at 0.
3. **A ROM whose path isn't UTF-8 stopped the library from saving** for the rest of the run, since
   TOML can't store such a path. Such a game is now left out of the library, as the scan already
   did, and such a library folder is refused with a message.
4. **A `--scale` window could stay black.** It waited on the "which model?" question, which it never
   shows. It now continues on the model of the save, for that run only.
5. **MBC5 turned RAM on for any value whose low four bits are 0xA.** It now takes only 0x0A, as
   SameBoy and the hardware do. No test ROM or benchmark game changed.
6. **Damaged save states:**
   - A state that adds or drops the Super Game Boy is refused before anything changes. Before, the
     refused load still reset the player's border, palette and last bordered frame.
   - MBC1, MBC2, MBC5 and HuC1 now cut their registers to their widths on load, as MBC3 already
     did.
   - Two PPU tests that were meant to prove such states are refused never reached the check.
     They do now, and each fails without it.
7. **Files players edit by hand:**
   - Cheats from a cheats file are checked and put in normal form. A code that can't be used stays
     off and is named.
   - A key bound to two actions keeps one, the controller's pause menu first.
   - A volume that isn't a number or is out of range is clamped.
   - A window size too large for any screen is cut to 16,384 pixels a side.
   - A file over 16 MiB is refused as a game instead of read whole.
8. **ROM headers:** a ROM was refused for a junk RAM size byte even when its cartridge type has no
   RAM. A save file still gave such a cartridge a RAM buffer.
9. **The app:**
   - Menus and every pause menu page now scroll to the row the D-pad is on.
   - The fast forward badge no longer shows while the game is paused, so it can't end up in a
     scene's preview.
   - A library folder inside another one is watched once. Before, the second watch turned the first
     one's subfolders off.
10. **The RetroArch core:**
    - It logs through RetroArch without its own lock held.
    - It stores the core before sending the memory map, so RetroArch can read memory while it
      handles the map.
    - It says why a state didn't load.
    - Its clock tests allow for a slow machine.
11. **Tools and CI:**
    - Flathub's linter ran unpinned, as root, with the whole checkout read-write, before the
      Flatpak that releases publish was uploaded. It is now pinned by digest and reads only what it
      needs, after the upload. The nightly review reports a newer image.
    - The RetroArch install that hit its time limit last night now skips its recommended packages
      and has a time limit of its own.
    - A stalled test now fails on its own instead of ending the whole test ROM run.
    - The benchmark's screenshots of ROMs sharing a file name overwrote each other.
    - The save-state check ignored `CARGO_TARGET_DIR`.
    - The Shootout rank would count Nubo against itself once it is published.
    - The nightly metrics and rotation treated any read error as "no file", and would have written
      over the wiki's history.
    - The screenshots left GNOME Shell running when the portal check failed.
    - Cargo's resolver 3 keeps updates within `rust-version`. Every crate is at its newest
      compatible release, and the fuzz targets run every model.
