# Code review of 25 October 2026

A review of the whole repository on 2026-10-25, at `main` 16f1994 (App: document the app's fields
and messages that had no doc comment, #300). `main` didn't move during the review. It looked for
bugs, breaks of the rules in `AGENTS.md`, idiomatic Rust, the code style, doc comments and the docs.
The maintainer asked for larger fixes too, not only small ones, and for an issue for each real
finding that isn't fixed. So 99 of the 104 findings are fixed on five theme branches, each a pull
request of its own. Two are filed as issues, #301 and #302, and two are notes in this report. One
didn't hold. No issue was open when the review started: every issue of the last review (#270 to
#279, #285 to #287) was closed, and there was no nightly issue.

## How it was done

- **Ten area reviews**, one per part of the code: the CPU and emulator API, the address bus

  RetroArch core, the tools and small crates, xtask with the workflows, and the docs. Each read every
  file of its area in full and traced the path from a real input to each failure.
- **104 findings in all:** 29 bugs, 1 rule, 23 idioms, 23 style points and 28 places where the

  - `EXTRA-4`: the second reviewer's safety net against the next bug of that kind.
- **Every finding was checked again** in the code before it was fixed or filed (the ledger):
  - 99 fixed: 26 docs, 22 style, 16 idioms, 23 bug fixes and 12 tooling;
  - 2 filed as issues;
  - 2 notes;
  - none moot;
  - 1 wrong: `EXTRA-2`'s lines are a Markdown table row, a usage line and two lines of `--help`
    text, which can't be wrapped.

  One fix was checked against SameBoy and Pan Docs: SC bit 1 picks the fast serial clock only in
  CGB mode.
- **A second reviewer**, a separate Claude Code session that could not push, checked every commit
  in eight rounds: one per branch, one for the merges, and two for the fuzzing fix and its safety

  - compared the end states of the 19 test ROMs whose fingerprints changed, field by field (see

  - reported six wording and wrapping slips; five are fixed, and the sixth is a note below.
- **Its stress tests:**
  - 18,860 runs, with 3,772,000 save-and-load checks: every test ROM on DMG, SGB, CGB-0 and CGB-E,
    saved and loaded at many points of each run;
  - 18,000 more checks: the benchmark games and the Super Game Boy multiplayer ROMs on all 12

### The bugs fixed

The most important first:

1. **A damaged save state could make the core panic.** A state may hold the time since power-on
   up to its limit, 2^62 dots. Running from there passes the limit, so the next state the emulator
   wrote failed its own check. Rolling back a failed load then panicked. A player could reach it
   by loading such a state and then any state that fails. RetroArch's run-ahead reached it on the
   next frame. A state now never stores more than the limit. The `state_fields` fuzz target found
   it (EXTRA-3). And should a state the emulator just wrote ever fail to read back, the emulator
   now starts over from power-on instead of panicking (EXTRA-4).
2. **Battery saves Nubo can't use were written over.** A `.sav` under 512 bytes, such as a packed
   save from another emulator, or an `.rtc` of the wrong size was treated as missing. The game's
   first save then replaced it. Such a file is now left alone, as an unreadable one already was,
   and the player is told (FRONTEND-4).
3. **The game froze when the sound device went away.** Only the sound card's callback paced the
   game, so unplugging the headphones stopped it for good. The session now paces by the clock
   once the device reports it is gone (FRONTEND-2).
4. **Ctrl+O on the desktop could panic.** rfd unwraps a failed read of the picked file, and the
   picker skipped the 16 MiB limit every other way of opening a game has. The desktop now reads the
   file like any other game, and the browser checks the size first (APP-1).
5. **RetroArch's Restart used the old Model or Cartridge clock option.** RetroArch runs no frame
   while its menu is open, and only a frame read the options. A restart now reads them first
   (LIBRETRO-1).
6. **The core's emulation:**
   - Game Genie codes patched the boot ROM's own code while it ran, which could hang the boot
     (CORE-BUS-1).
   - A DMG game on a Game Boy Color could switch on the fast serial clock, which only CGB mode
     has (CORE-BUS-2).
   - A ROM could push the noise channel's counter past 0x7FFF, which made its own save states
     unloadable, and to 0xFFFF, where debug builds panicked (CORE-APU-SGB-1).
   - With the LCD off after OAM DMA, the PPU ran dot by dot until the LCD came back on. It now runs
     lazily again. The result was always the same, so only the speed changed (CORE-GPU-2).
7. **Damaged save states:** a few more values no console can have are now corrected or refused:
   - the low four bits of the flags register;
   - JOYP's select bits;
   - the Super Game Boy's player count;
   - the VRAM DMA length;
   - the PPU's STOP blocks.

   Nubo never writes any of them (CORE-CPU-2, CORE-BUS-3, CORE-GPU-3).
8. **An MBC3 clock game wrote and synced its `.rtc` file every second**, on the emulator thread.
   The clock now waits a minute between writes. It is still written when the game pauses or stops
   (FRONTEND-3).
9. **The app:**
   - The "tell you about updates?" question came up over the very first game, on a start with a
     game (APP-2).
   - A `--fresh` run offered "Add folder", which then said no games were found (APP-4).
10. **The library:**
    - A title-screen capture kept every sound sample of a game that stops drawing, about 25 MB
      (CORE-APU-SGB-2).
    - Title-screen captures and box-art checksums read the game file without the size limit
      (FRONTEND-5).
    - A box-art download over the limit was cut short silently, and a cut game list was kept for
      good (FRONTEND-6).
11. **The RetroArch core:**
    - The picture's size outlived a game and its core, so one test depended on the order the tests
      ran in (LIBRETRO-2).
    - The log didn't say why a cheat code was refused (LIBRETRO-4).
    - One more clock test depended on the machine's speed (LIBRETRO-3).
12. **The PPU's test:** nothing checked that the quiet dots the PPU promises the bus hold nothing the
    CPU can see. Only the nightly eager comparison would have noticed. The random scenes now check
    it (CORE-GPU-1).
13. **Tools and CI:**
    - The `rom` fuzz target never booted a header whose logo or checksum wasn't Nintendo's.
      Nubo's boot ROMs check neither, so the fuzzer skipped every change to the cartridge type,
      sizes and flags (TOOLS-1).
    - One panicking ROM ended a whole `cargo benchmark` run without naming it (TOOLS-2).
    - The Windows app and the Windows RetroArch core shared one build cache, so one of them rebuilt
      from scratch every night (XTASK-1).
    - A failed wiki clone lost the night's metrics silently (XTASK-3).
    - The screenshot and game lists treated any read error as an empty list, so their tests could
      pass on nothing (XTASK-4).
    - A new check, `cargo xtask rust-version`, stops a dependency that needs a newer Rust than
      the Flatpak's. Before, only the nightly Flatpak build found it (XTASK-7).
